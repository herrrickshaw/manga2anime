# manga2anime

<!-- how-to-use-with-ai -->
> **New here?** See [How to use this repo with AI (Claude, Gemini, ChatGPT)](HOW_TO_USE_WITH_AI.md) — clone it, paste it into an AI tool, and ask in plain English.

Experiments in animating a static manga/anime-style panel into a short video clip. Two routes are
tracked: (1) **open-source image-to-video models** (Stable Video Diffusion, ToonCrafter) driven through
their free hosted demos on Hugging Face Spaces / Colab — never on local hardware — and (2) a
**fully procedural renderer** ("The Lantern Oracle") that draws an original Art Nouveau / tarot-style
panel with Pillow and encodes a 6 s seamless loop with ffmpeg. Outputs are MP4 clips and PNG stills in
`assets/`.

> Status: research-only. Source art is CC0 / public domain (see [Data sources](#data-sources)); the
> procedural panel is an original character and composition. No model weights are stored in this repo.

## What it does
- `original/svd_run.py` sends a 1024x576 still to the public `multimodalart/stable-video-diffusion`
  Space via `gradio_client` and saves the returned clip (seed 42, 6 fps, configurable motion bucket).
- `original/render_lantern_oracle.py` renders 144 frames (720x960, 24 fps, 2x supersampled) of an
  animated oracle — star field, rotating astrolabe, mosaic halo, 12 procedural sigils, wind-blown hair,
  pulsing lantern with glow and motes — and encodes `assets/lantern_oracle.mp4` plus a poster PNG.
- Every frame is a pure function of loop phase `t ∈ [0, 1)`, so the clip loops without a seam.
- Records the ToonCrafter two-keyframe attempt, including the two dependency bugs found in the
  community Colab notebook (see [Limitations](#limitations-and-known-issues)).

## Quick start
```bash
git clone https://github.com/herrrickshaw/manga2anime.git
cd manga2anime
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt      # numpy, Pillow, gradio_client
python original/render_lantern_oracle.py          # -> assets/lantern_oracle.mp4 + _poster.png (needs ffmpeg on PATH)
python original/svd_run.py assets/frame1_source.png out.mp4 [motion]   # hosted SVD Space; needs network
```

## How it works

| Stage | Module / function | Output |
|---|---|---|
| Static precomputes (gradient, star/mote scatter, sigils, arch mask, font) | `render_lantern_oracle.background/scatter/sigils/outside_mask/title_font` (lazy, cached) | in-memory |
| Per-frame drawing on a 1440x1920 canvas | `draw_stars → draw_astrolabe → draw_halo → draw_sigils → draw_figure → draw_lantern → draw_motes` | PIL image + glow layer |
| Composite: Gaussian-blurred glow screened over the scene, outside-arch inked, frame + title | `render(t)` | 720x960 RGB frame (Lanczos downsample) |
| I/O edges | `write_frames()` (PNG sequence, poster at frame N/4), `encode_video()` (ffmpeg libx264, crf 18) | `assets/lantern_oracle.mp4`, `assets/lantern_oracle_poster.png` |
| Hosted SVD | `svd_run.run_svd(src, out, motion, client_factory=gradio_client.Client)` | `out.mp4` |

Design decisions:
- **Hosted GPUs only.** The dev machine (M1, 8 GB RAM) has no CUDA GPU, so model runs go through each
  project's public Space / Colab notebook; nothing downloads weights locally.
- **Procedural, deterministic rendering.** Stars/motes come from one seeded RNG stream (`SCATTER_SEED=7`)
  and sigils from `SIGIL_SEED_BASE + i`, so the clip is reproducible frame-for-frame.
- **Gradio client injected.** `run_svd()` takes a `client_factory` so tests fake the Space; the real
  client is imported only when the function runs.

## Configuration
No environment variables or secrets. Rendering constants (`W, H, S, FPS, SECONDS`, seeds, palette,
font candidates) live at the top of `render_lantern_oracle.py`; the font falls back to Pillow's default
when the macOS serif fonts are absent. `svd_run.py` fixes `SEED=42`, `FPS=6`, `DEFAULT_MOTION=100`.

## Limitations and known issues
- **ToonCrafter is inconclusive.** The Space `Doubiiu/tooncrafter` hit its anonymous ZeroGPU quota
  (shared across all Spaces, exhausted by the SVD run; resets ~24 h, or needs a signed-in HF account).
- The fallback `camenduru/ToonCrafter-jupyter` Colab (free T4) pins 2023-era exact versions
  (`torch==2.0.0`, `pytorch_lightning==1.9.3`, ...) with no wheels for Colab's Python 3.13; failed builds
  silently aborted the rest of `pip install -r requirements.txt` (so `decord` and `pytorch_lightning`
  never installed). Fix: install `decord` directly and strip the pins (`sed -i 's/==.*//' requirements.txt`).
- After that fix the app downloaded the ~3.94 GB CLIP checkpoint, but the browser tab driving the
  notebook became unresponsive before the Gradio server's launch could be confirmed. A re-run in a stable
  browser session is still needed.
- `render_lantern_oracle.py` shells out to `ffmpeg`; without it on `PATH` the frames render but encoding fails.
- `svd_run.py` depends on a third-party Space staying online with the same `/video` API signature.
- Commercial closed tools (DomoAI, Anifusion, Kling AI) offer similar manga-panel animation but are not
  open source; this repo tracks open-source equivalents for the same use case.
